  <name>Task 1: Create feeds store and history store with atomic persistence</name>
  <files>src/state/feeds-store.ts, src/state/history-store.ts</files>
  <action>
Create both state stores as factory functions following the research patterns:

1. **src/state/feeds-store.ts** -- Feed subscription CRUD:
   - Import `readFileSync`, `existsSync` from `node:fs`
   - Import `atomicWriteSync` from `./atomic-write.js`
   - Import `Feed` type from `../types.js`
   - Export `createFeedsStore(filePath: string)` factory function
   - Internal `readAll()`: if file does not exist, return `[]`. Wrap `JSON.parse(readFileSync(...))` in try/catch -- on parse error, return `[]` (corrupt file recovery per research Pitfall 3)
   - Internal `writeAll(feeds: Feed[])`: call `atomicWriteSync(filePath, JSON.stringify(feeds, null, 2))`
   - Return object with methods:
     - `getAll(): Feed[]` -- returns all feeds
     - `add(feed: Feed): void` -- reads all, pushes new feed, writes all
     - `remove(url: string): boolean` -- reads all, filters out matching URL, writes if changed, returns whether anything was removed
     - `has(url: string): boolean` -- returns whether any feed has this URL

2. **src/state/history-store.ts** -- Download history tracking:
   - Import `readFileSync`, `existsSync` from `node:fs`
   - Import `atomicWriteSync` from `./atomic-write.js`
   - Import `DownloadHistory` type from `../types.js`
   - Export `createHistoryStore(filePath: string)` factory function
   - Internal `readAll()`: if file does not exist, return `{}`. Wrap `JSON.parse(readFileSync(...))` in try/catch -- on parse error, return `{}` (corrupt file recovery)
   - Internal `writeAll(history: DownloadHistory)`: call `atomicWriteSync(filePath, JSON.stringify(history, null, 2))`
   - Return object with methods:
     - `isDownloaded(feedUrl: string, guid: string): boolean` -- reads history, returns `history[feedUrl]?.includes(guid) ?? false`
     - `markDownloaded(feedUrl: string, guid: string): void` -- reads history, initializes array for feedUrl if missing, pushes guid if not already present, writes back
     - `getDownloadedGuids(feedUrl: string): string[]` -- returns array of GUIDs for a feed URL, or empty array

CRITICAL for STATE-02: The history store MUST NOT check the filesystem for MP3 files anywhere. It only reads/writes its own JSON file. The `isDownloaded` method checks the JSON data, NOT whether a file exists on disk.

Both stores use `atomicWriteSync` (STATE-03) -- never raw `writeFileSync`.
  </action>

  <name>Task 2: Create filename sanitization utility</name>
  <files>src/utils/sanitize.ts</files>
  <action>
Create the filename sanitization module using filenamify:

1. **src/utils/sanitize.ts**:
   - `import filenamify from 'filenamify'`
   - Define constants: `MAX_FILENAME_LENGTH = 200`, `REPLACEMENT_CHAR = '-'`
   - Export `sanitizeFilename(name: string): string`:
     - Returns `filenamify(name, { maxLength: MAX_FILENAME_LENGTH, replacement: REPLACEMENT_CHAR })`
     - Used for episode filenames
   - Export `sanitizeDirName(name: string): string`:
     - Calls filenamify with same options
     - Additionally trims leading/trailing whitespace and dashes that may result from sanitization: `.replace(/^[-\s]+|[-\s]+$/g, '').trim()`
     - If result is empty string after trimming, return `'unknown-podcast'` (fallback for edge case where input is entirely illegal characters)
     - Used for podcast folder names (per research Pitfall 4: MUST sanitize folder names too, not just filenames)

Set maxLength to 200 (not the filenamify default of 100) per research Pitfall 5 -- gives room for long titles while staying well under FAT32's 255-char limit.
  </action>
