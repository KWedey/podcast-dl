<task type="auto">
  <name>Task 1: Create CLI entry point with Commander and wire all commands</name>
  <files>src/cli.ts</files>
  <action>
Create the CLI entry point following the research Pattern 3 precisely:

1. **src/cli.ts** -- First line MUST be the shebang: `#!/usr/bin/env node`
2. Import `Command` from `'commander'`
3. Import `registerAddCommand` from `'./commands/add.js'`
4. Import `registerRemoveCommand` from `'./commands/remove.js'`
5. Import `registerListCommand` from `'./commands/list.js'`
6. Create program: `const program = new Command()`
7. Configure program:
   - `.name('podcast-dl')`
   - `.description('Download podcast episodes from RSS feeds')`
   - `.version('0.1.0')`
8. Register all commands:
   - `registerAddCommand(program)`
   - `registerRemoveCommand(program)`
   - `registerListCommand(program)`
9. Call `program.parseAsync(process.argv)` -- MUST be `parseAsync`, NOT `parse`. The add command is async (fetches URLs). Using parse() would cause the program to exit before the fetch completes, producing silent failure with no output.

CRITICAL: Use `parseAsync()`, not `parse()`. This is the single most common Commander + async mistake per research Pitfall 1.

After creating the file, compile with `npx tsc` and verify the shebang appears in `dist/cli.js`.
  </action>
  <verify>
Run `npx tsc --noEmit` -- zero errors.
Run `npx tsc` to compile.
Verify shebang: `head -1 dist/cli.js` should show `#!/usr/bin/env node`.
Run `npx tsx src/cli.ts --help` -- should show "Download podcast episodes from RSS feeds" with add, remove, list subcommands.
Run `npx tsx src/cli.ts --version` -- should print "0.1.0".
Run `npx tsx src/cli.ts add --help` -- should show "Subscribe to a podcast RSS feed" with url argument.
Run `npx tsx src/cli.ts remove --help` -- should show "Unsubscribe from a podcast feed" with url-or-name argument.
Run `npx tsx src/cli.ts list --help` -- should show "List subscribed podcast feeds".
  </verify>

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Verify complete feed management workflow end-to-end</name>
  <action>
Human verifies the complete CLI feed management system: add feeds with RSS validation, remove feeds by URL or name, list subscribed feeds. Built across Plans 01 and 02 on top of Phase 1 foundation.

Test the full feed management workflow using the dev script:

1. **List with no feeds (empty state):**
   ```
   npx tsx src/cli.ts list
   ```
   Expected: Yellow message "No feeds subscribed. Use podcast-dl add url to add one."

2. **Add a valid RSS feed:**
   ```
   npx tsx src/cli.ts add https://feeds.simplecast.com/54nAGcIl
   ```
   Expected: Green success message with the podcast name (this is The Daily from NYT).
   If that URL does not work, try: `https://feeds.megaphone.fm/hubermanlab`

3. **Add the same feed again (duplicate check):**
   ```
   npx tsx src/cli.ts add https://feeds.simplecast.com/54nAGcIl
   ```
   Expected: Yellow warning "Feed already subscribed" -- should NOT add a duplicate.

4. **Add an invalid URL (not RSS):**
   ```
   npx tsx src/cli.ts add https://www.google.com
   ```
   Expected: Red error message indicating the URL is not a valid RSS feed.

5. **Add a completely invalid URL:**
   ```
   npx tsx src/cli.ts add not-a-url
   ```
   Expected: Red error about invalid URL format.

6. **List feeds (should show the added feed):**
   ```
   npx tsx src/cli.ts list
   ```
   Expected: Shows the feed name and URL.

7. **Remove by name (case-insensitive):**
   ```
   npx tsx src/cli.ts remove "the daily"
   ```
   Expected: Green success message "Unsubscribed from ..."

8. **List again (should be empty):**
   ```
   npx tsx src/cli.ts list
   ```
   Expected: Yellow empty-state message again.

9. **Persistence check -- add a feed, then verify the file exists:**
   ```
   npx tsx src/cli.ts add https://feeds.simplecast.com/54nAGcIl
   cat ~/.podcast-dl/feeds.json
   ```
   Expected: JSON file with the feed entry.
  </action>
